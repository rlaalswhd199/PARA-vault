## 1. 프로젝트 개요

### 목표
단백질이 리간드 결합 전(Apo)과 결합 후(Holo) 구조 사이의 conformation change를 예측.  
Flow matching으로 Apo → Holo ODE trajectory를 학습.

### 핵심 아이디어
- **Flow Matching**: `u = x1 - x0` velocity target, Euler ODE로 inference
- **ICS (Internal Coordinate System)**: 단백질 backbone을 내부좌표계로 표현
  - CA-only 5-dim: `[d_CA, sinθ, cosθ, sinφ, cosφ]`
  - Full backbone 9-dim: `[φ, ψ, ω, τ, ...]` (각도 6개 + 거리 3개)
- **NERF**: ICS → Cartesian 좌표 역변환 (chain 방식, 오차 누적됨)

### 아키텍처
- DiT (Diffusion Transformer) 스타일: adaLN-Zero + RoPE
- Condition: ESM-3 (1536-dim 서열 임베딩) + Featurizer (145-dim 구조 특성)
- 시간 임베딩: Fourier (256-dim)

## 2. ICS 각도 표현 방식

### sin/cos 인코딩을 쓰는 이유
ICS에서 각도를 raw radian (`θ`) 대신 `(sinθ, cosθ)` 쌍으로 저장한다.

**이유**: 각도는 **주기적(circular)** 공간에 있어서, `-π`와 `+π`는 수학적으로 같은 방향이지만 숫자로는 2π만큼 떨어져 있다. neural network가 이 불연속성을 학습하기 어렵다.

`(sinθ, cosθ)` 인코딩은:
- 주기적 불연속성 제거 → 학습이 안정적
- 원래 각도 복원: `θ = atan2(sinθ, cosθ)`
- 단점: 차원이 2배 (θ 1개 → sinθ, cosθ 2개)

### CA-only 5-dim 구성
```
[d_CA, sinθ, cosθ, sinφ, cosφ]
  ↑      ↑─────────↑  ↑────────↑
  CA간   bond angle     dihedral angle
  거리   (θ: 0~π)       (φ: -π~π)
```

## 4. 시행착오 기록

### 4-1. CA-only 모델: loss↓ RMSD oscillation 문제 (핵심 버그)

**현상**: 학습 loss는 잘 내려가는데, RMSD는 전혀 개선되지 않고 oscillate함.

**원인 1: `_wrap_angular` 9-dim bug**
- `ode_solver.py`에서 `wrap_fn=None`이면 `_wrap_angular` (9-dim full_backbone용)가 기본 적용됨
- CA-only (5-dim)에 9-dim wrap을 적용 → `atan2`가 d_CA(거리값)에 적용되어 ODE step마다 좌표 왜곡
- **수정**: `_wrap_ca_only` 함수 추가, `generate_holo()`에서 명시적으로 전달

**원인 2: OOD at inference (NERF Lever Arm Effect)**
- `xt_input=True` 학습: `x_t = x0 + t*(x1-x0)` linear interpolation manifold에서 학습
- ODE inference: 매 step마다 `x_t`가 manifold에서 벗어남 (drift 발생)
- ICS에서 미세한 drift ε → NERF 역변환 시 ~60-100x Cartesian RMSD 증폭
  - ε=0.001 → ICS 공간 오차 0.001 → Cartesian RMSD ~0.10Å (103.9x 증폭)
  - Cartesian은 동일 ε → ~0.0017Å (1.7x에 그침)
- ODE steps가 많을수록 drift 누적 → steps=1이 오히려 최적 (in-distribution)

**수정 시도**:
- `time_sampling: "grid"` → t ∈ {0, 0.1, ..., 0.9} 고정 grid → ODE steps=10과 정확히 매칭되어 OOD 감소
- → 하지만 steps≠10 비교 시 편향이 생기므로, 최종적으로 `time_sampling: "uniform"`으로 변경

### 4-2. Cartesian 모델: 좌표 origin 붕괴 bug

**현상**: Cartesian 모델 inference 시 pred 좌표가 origin 근처로 완전히 붕괴 (pred std ~1.8Å, 정상은 ~20Å)

**원인**: `ode_solver.py` 89번째 줄
```python
_wrap = wrap_fn if wrap_fn is not None else _wrap_angular  # 버그!
```
- `generate_holo()`에서 cartesian 모드일 때 `wrap_fn=None`을 넘김
- → `_wrap_angular`가 (L,3) X,Y,Z 좌표에 적용
- → `atan2(sin(x), cos(x))`가 ~15Å 범위의 좌표를 [-π, π]로 압축
- → 10 ODE step 후 완전히 origin 근처로 붕괴

**수정**: `_wrap_identity` 함수 추가, cartesian 모드에서 명시적으로 전달
```python
# ode_solver.py
def _wrap_identity(backbone):
    return backbone  # no-op

# crypticflow.py generate_holo()
wrap_fn=_wrap_ca_only if self.feature_mode == "ca_only" else (
    _wrap_identity if self.feature_mode == "cartesian" else None
)
```

**수정 후 결과** (4JNF, L=212, first RMSD=27.62Å):
- 수정 전: RMSD(pred, holo) = 36.46Å (origin 붕괴)
- 수정 후: RMSD(pred, holo) = **3.95Å** (5000 epoch 학습 기준)

### 4-3. 진단 방법: velocity 분리 테스트

모델이 velocity를 제대로 학습했는지 확인하는 방법:
```python
# flow_network 직접 호출
v_pred = model.flow_network(apo_bb, t_val, featurizer, esm)
print(f'GT velocity std={u_gt.std():.4f}')
print(f'Pred velocity std={v_pred.std():.4f}')
```
- velocity std가 GT와 비슷하면 학습은 정상 → ODE solver 문제
- velocity std가 0에 가까우면 모델이 학습 실패

| 1 | 1.80Å (최적) |
| 10 | 3.98Å |

→ steps 증가할수록 RMSD 악화. ICS에서 ODE drift가 NERF로 증폭되기 때문.

## 6. Cartesian Flow Matching 모델 구현

### 설계 결정
- **입력**: Kabsch align(holo→apo 기준) 후 CA 좌표 `(L, 3)`
- **정규화**: apo centroid=0 (Kabsch align으로 이미 정렬), holo도 동일 rotation 적용
- **velocity**: `u = holo_aligned - apo_centered` (단순 벡터 차이, angular wrap 없음)
- **wrap**: `_wrap_identity` (wrap 불필요)
- **decoder**: 없음 (backbone이 이미 3D 좌표)

### dataset.py 수정사항
```python
def kabsch_align(mobile, reference):
    """Kabsch 알고리즘: mobile을 reference에 최적 정렬 (translation 후 rotation)"""
    mob = mobile - mobile.mean(0)
    ref = reference - reference.mean(0)
    H = mob.T @ ref
    U, _, Vt = torch.linalg.svd(H)
    d = torch.linalg.det(Vt.T @ U.T)
    D = torch.diag(torch.tensor([1., 1., d]))
    R = Vt.T @ D @ U.T
    return mob @ R.T

# cartesian 모드 backbone 구성
ca_apo_centered  = coord_CA_apo - coord_CA_apo.mean(0)
ca_holo_aligned  = kabsch_align(coord_CA_holo, coord_CA_apo)
backbone_apo  = ca_apo_centered   # (L, 3)
backbone_holo = ca_holo_aligned   # (L, 3)
```

## 7. 실험 결과

### 실험 2: ICS vs Cartesian 비교 (2026-05-10 완료)

**설정**: hidden=256, layers=32, epochs=20000, `time_sampling: "uniform"`, `xt_input: true`  
**학습 job**: ICS(34354~34356), Cartesian(34348~34350)  
**스크립트**: `experiments/exp2_ics_vs_cart.py`  
**Figure**: `experiments/results/exp2_ics_vs_cart.png`

#### ODE steps별 RMSD (Kabsch align 후)

| Case | First RMSD | steps=1 | steps=2 | steps=5 | steps=10 | steps=20 | steps=50 |
|------|-----------|---------|---------|---------|----------|----------|----------|
| **ICS small** | 2.98Å | 0.374Å | 0.723Å | 0.796Å | 1.246Å | 1.580Å | 1.805Å |
| **ICS mid** | 4.64Å | 6.004Å | 7.104Å | **13.620Å** | 6.669Å | 7.030Å | 7.021Å |
| **ICS large** | 27.62Å | 0.759Å | 0.927Å | 0.944Å | 1.228Å | 1.338Å | 1.419Å |
| **Cart small** | 2.98Å | 0.0106Å | 0.0059Å | 0.0040Å | 0.0041Å | 0.0040Å | 0.0042Å |
| **Cart mid** | 4.64Å | 0.0097Å | 0.0062Å | 0.0050Å | 0.0049Å | 0.0048Å | 0.0049Å |
| **Cart large** | 27.62Å | 0.0291Å | 0.0264Å | 0.0255Å | 0.0257Å | 0.0270Å | 0.0265Å |

#### 핵심 발견

1. **Cartesian은 steps에 무관하게 안정적** — steps=1~50 전 구간에서 0.004~0.029Å 유지. ODE trajectory가 직선에 가깝게 학습되어 어느 step 수를 써도 안정적으로 도착지를 찾아감.

2. **ICS는 steps 증가할수록 RMSD 단조 증가** — small/large 모두 steps=1이 최솟값이고 steps가 늘수록 악화. 가설대로 ODE drift → NERF 증폭이 steps마다 누적됨.

3. **ICS mid의 비정상적 패턴** — steps=5에서 13.6Å로 급등 후 steps=10에서 6.7Å로 내려옴. ICS trajectory가 특정 step 수에서 불안정한 구간을 통과하는 것으로 추정.

4. **절대 성능 차이가 압도적** — 같은 아키텍처, 같은 데이터, 같은 학습 조건에서:
   - Cartesian best: 0.004~0.026Å (사실상 완벽 overfit)
   - ICS best: 0.37~6.0Å (최소 10배~1000배 차이)

#### 결론

> ICS 공간에서의 flow matching은 ODE inference 중 발생하는 미세한 drift가 NERF 역변환 시 ~100x 증폭되어(Lever Arm Effect), steps 수가 늘수록 Cartesian RMSD가 급격히 악화된다. 반면 Cartesian 공간에서는 ODE drift가 Cartesian RMSD에 직접 반영되므로 증폭 없이 steps에 robust하다. 동일 아키텍처 기준 Cartesian이 ICS 대비 10~1000배 낮은 RMSD를 달성한다.

#### ODE 동작 방식 재확인 (2026-05-10)

ODE는 **ICS 공간에서만** 전 구간을 적분하고 NERF는 마지막 한 번만 적용됨:
```
x_ICS(t=0) → [Euler × N steps, ICS 공간] → x_ICS(t=1) → NERF(1회) → 3D coords
```
즉, OOD는 ICS 공간에서 발생하고 그 결과가 NERF로 증폭되어 Cartesian에서 관측됨.

### 실험 2-B: ODE 매 step별 drift 분석 (2026-05-10)

**설정**: steps=10, NERF 증폭비 = (ICS→NERF Cartesian drift) / (Cartesian direct drift)

#### ODE drift 합계 (steps=10)

| Case | ICS feature drift (L2) | ICS→NERF drift (Å) | Cartesian drift (Å) | NERF 증폭비 |
|------|----------------------|-------------------|--------------------|-----------:|
| small (L=47) | — | 17.811Å | 2.980Å | **6.0x** |
| mid (L=140) | — | 99.415Å | 4.639Å | **21.4x** |
| large (L=316) | — | 60.715Å | 27.606Å | **2.2x** |

#### 핵심 발견

1. **NERF Lever Arm Effect 정량 확인** — ICS에서 같은 크기의 feature 변화가 NERF를 통과하면 Cartesian drift가 2.2x~21.4x 증폭됨. mid case(140 잔기)에서 가장 극단적.

2. **mid case 21.4x 증폭 이유** — 잔기 수와 단독으로 비례하지 않음. mid 단백질(3OIC)의 구조적 특성(긴 loop, extended chain)이 NERF 오차 전파에 특히 취약한 것으로 추정. 반면 large(316 잔기)는 2.2x에 그침 — globular/compact 구조라 오차가 부분적으로 상쇄될 수 있음.

3. **Cartesian drift는 RMSD에 직접 반영** — Cartesian 모델은 step당 2.98~27.6Å의 drift가 발생하지만 이는 ICS→NERF drift보다 낮고, 실제 RMSD(0.004~0.026Å)와 스케일이 일치하지 않음. → Kabsch alignment가 systematic translation을 제거하므로 absolute drift가 아닌 "정렬 후 잔차"가 RMSD. Cartesian ODE는 전반적으로 균일하게 이동하기 때문에 정렬 후 RMSD가 매우 작음.

### 실험 2-C: OOD 복원력(Resilience) 분석 (2026-05-10)

**설정**: t=0.5에서 clean x_t에 OOD noise ε 추가 후 velocity cosine similarity 측정  
- cosim(v_θ, u_GT) ≈ 1.0 → 올바른 방향 유지 (복원력 있음)  
- cosim ≈ 0.0 → 방향 상실 (복원력 없음)

#### Cosine Similarity: ICS vs Cartesian

| Case | ε=0 (ICS) | ε=0.1 (ICS) | ε=1.0 (ICS) | ε=5.0 (ICS) | ε=0 (Cart) | ε=0.1 (Cart) | ε=1.0 (Cart) | ε=5.0 (Cart) |
|------|----------|------------|------------|------------|-----------|-------------|-------------|-------------|
| small | 0.988 | 0.191 | 0.036 | 0.015 | 1.000 | 0.990 | 0.626 | 0.025 |
| mid | 0.993 | 0.203 | -0.009 | 0.000 | 1.000 | 0.943 | 0.702 | 0.070 |
| large | 0.997 | 0.159 | 0.005 | 0.003 | 1.000 | 1.000 | 0.992 | 0.850 |

#### 1-step 예측 RMSD under OOD noise

| Case | ε=0 (ICS) | ε=1.0 (ICS) | ε=5.0 (ICS) | ε=0 (Cart) | ε=1.0 (Cart) | ε=5.0 (Cart) |
|------|----------|------------|------------|-----------|-------------|-------------|
| small | 2.279Å | 17.721Å | 7.764Å | 1.492Å | 0.937Å | 1.314Å |
| mid | 15.153Å | 29.389Å | 23.918Å | 2.320Å | 1.764Å | 2.171Å |
| large | 10.642Å | 16.313Å | 20.557Å | 13.795Å | 13.795Å | 13.793Å |

#### 핵심 발견

1. **ICS는 ε=0.1에서 즉시 방향 상실** — clean에서 cosim=0.988~0.997이던 ICS 모델이 ε=0.1 노이즈만으로 0.159~0.203으로 급락. 이는 ICS 공간에서의 작은 perturbation이 실제로 매우 큰 off-manifold 이동임을 의미.

2. **Cartesian large는 ε=5.0에서도 cosim=0.850** — 가장 극적인 대조. Cartesian 공간에서의 noise는 3D 좌표에 직접 추가되므로, 모델이 학습한 velocity 방향이 noise에 robust. 특히 large 단백질(316 잔기)은 signal-to-noise ratio가 높아 더 안정적.

3. **ICS ODE의 근본 문제 재확인** — 매 Euler step에서 ICS x_t가 manifold를 살짝 벗어나면(= 정상 단백질이 가질 수 없는 ICS 값), 모델의 velocity 예측이 완전히 틀어짐. 이것이 steps 수가 늘수록 ICS RMSD가 악화되는 직접적 원인.

4. **Cartesian small/mid의 ε=5.0 cosim 하락** — small(0.025), mid(0.070)로 Cartesian도 큰 noise에서는 방향 상실. 단, 이 스케일(ε=5.0 → 좌표에 5Å급 noise)은 물리적으로 비현실적이며, 실제 ODE step에서 발생하는 drift는 훨씬 작음.

#### 결론

> **ICS 모델은 OOD에 구조적으로 취약하다.** ICS 공간은 정상 단백질 backbone이 점유할 수 있는 manifold가 매우 좁기 때문에, ODE 적분 중 미세한 오차(ε≈0.1)만으로도 모델이 완전히 방향 감각을 잃는다. Cartesian 공간은 ε=1.0 수준의 noise에서도 cosim=0.6~0.99를 유지하며, 특히 large 단백질에서 ε=5.0에서도 0.85를 유지하는 강한 복원력을 보인다. 이는 **Cartesian flow matching이 ICS에 비해 ODE inference 중 OOD 상황에 훨씬 robust하다**는 것을 실험적으로 입증한다.
